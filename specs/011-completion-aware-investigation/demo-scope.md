# Immediate demo scope

The user's latest instruction prioritizes the smallest working happy path with
core TDD coverage. This milestone supersedes the earlier requirement to complete
all L01–L18 checks before making an interface available for demo; it does not
claim full feature acceptance.

Deliver the actual `trace-description-v1` producer output through semantic
ingestion, one bounded follow-up, reassessment and structured result. Use a
scripted assessor and injected deterministic operation for an offline reproducible
demo. No live-model diagnosis or benchmark accuracy claim follows from that check.

The public API uses detached JSON-compatible dictionaries rather than a large
domain type hierarchy. Scope includes case identity, deployment, requested
projection and incident count. The demo uses component/reason projection.
Callbacks execute in-process with bounded attempt counts; this does **not** enforce
hard wall-clock cancellation of a non-cooperative callback. No paid calls are made.

Core TDD covers evidence preservation/unknowns, invalid input, follow-up then
completion, rejection of unsupported completion, and bounded best-guess fallback.
Luna extra-high workers own ingestion and investigation modules separately.
Review all delivered production, test, example and packaging files before handoff.

Defer S01 compatibility, subprocess cancellation, hard time/cost limits, advanced
retry/progress policies, exhaustive projection fixtures, all L01–L18 acceptance,
runtime persistence integration and held-out diagnosis evaluation. These remain
broader feature obligations, not blockers to an honestly qualified demo-ready state.
