# Specialize trace extraction for the Track-1 bundle, not its development deployment

Track-1 supplies large, unsorted trace CSV partitions and evaluates the agent on another deployment of the same shop. Adopt a deterministic, provenance-preserving **Track-1 trace extraction pipeline**: validate the mounted bundle, select candidate spans by an explicit investigation policy, recover their recorded traces across the available inventory, and expose qualified execution evidence. Specialize the adapter to the documented bundle layout and trace fields while discovering dates, recording components, operations, types, and statuses from the mounted deployment.

This refines [ADR 0003](0003-indexed-telemetry-retrieval.md), using the [short-window experiment](../research/experiments/short-window-baselining.md) as implementation evidence. It does not select a production baseline, replace [ADR 0004](0004-qualified-contextual-baselines.md), or claim that trace extraction alone identifies an incident.

## Decision and boundaries

1. **Bind to a dataset contract, not a case lookup.** Read the supplied `telemetry/<date>/trace/trace_span.csv` inventory and the nine documented fields. Preserve raw strings and unknown values; validate structural schema changes explicitly. Do not hard-code March 20/21, 70 rows, 57 windows, `frontend-0/1/2`, guide cardinalities, fault times, or expected components as runtime invariants. These remain identified development fixtures. Bundle identity plus deployment scopes trace IDs; span identity adds the span ID.
2. **Separate selection from recovery.** Root-start selection, component/time selection, and explicit trace-ID expansion are distinct operations. A frontend-root view is an initial consumer policy, not the definition of all traces. Freeze its observed component allowlist and entry-operation rule from the supplied deployment; unknown entry semantics are unavailable, not a license to strip suffixes or invent equivalence. After selecting a trace, retrieve every matching recorded span across available partitions, including records outside the selection interval. Time buffers and ordered-prefix scans cannot certify recovery.
3. **Use a rebuildable local access layer.** Retain ADR 0003's SQLite choice, with time, trace-identity, and component access paths, streaming ingestion, bounded trace batches, and a scan-based correctness oracle. Reuse requires the same source content, parser/schema version, deployment identity, and completed inventory. Construct replacements separately and publish only completed views; interrupted builds and changed sources cannot masquerade as complete caches. Preparation is charged to runtime, not hidden in developer preprocessing.
4. **Preserve evidence before interpreting it.** Retain raw records, source content hashes, relative file paths, and logical CSV record locators. Do not overwrite duplicate identities. Report identical duplicates and conflicting records separately, and keep logical observations distinct from physical record counts. Resolve parent links only within the same trace and deployment; preserve same-emitter ancestry without converting it automatically into a service dependency. An RPC operation names observed work, not a proven target replica.
5. **Keep quality dimensions independent.** Source/retrieval coverage, identity resolution, parent-graph quality, duration validity, and reference eligibility are separate fields. Missing parents, disconnected records, cycles, multiple roots, and truncation remain visible. Invalid duration can make timing unavailable without concealing a resolvable parent relation. A fully searched inventory still cannot prove complete instrumentation. Empty recorded children and unknown structure are distinct.
6. **Declare timing semantics.** Trace starts are epoch milliseconds; prompt calendar times use UTC+8. Metrics/logs use seconds if later joined. Raw duration is a different field: the local audit supports a provisional microsecond interpretation, not an authoritative producer guarantee. Version that interpretation and retain raw values. Compute derived endpoints with integer arithmetic, preserve start-time precision, and do not infer network transit time, serial execution, success, or causality from parent/child timing alone. Clock skew and instrumentation uncertainty remain qualifications.
7. **Leave comparison policy above extraction.** Emit root duration, recovered endpoints, direct-child operation/type sets and multisets, source references, and quality when derivable. Keep observations that cannot enter a particular cohort. Strict pre-cutoff reference eligibility requires all known recovered endpoints to be before the cutoff and sufficient recorded coverage; excluded, unresolved, and unmatched observations remain accounted for. The experiment's five-minute C1 pooled policy and count thresholds are consumer configuration, not extraction defaults.
8. **Honor the scoring boundary.** Accept public task scope and preserve original case IDs, failure count, and requested fields. Neither the number of trace candidates nor the number of suspicious spans is constrained to equal the supplied incident count. No extraction path reads answer files, `scoring_points`, cached predictions, or hidden upstream data. An unavailable trace comparison is evidence uncertainty; the downstream diagnoser still owns Track-1's best-guess answer, exact component names, requested incident count, field ordering, and UTC+8 output contract under [ADR 0008](0008-isolated-evaluator-compatibility.md).

## Alternatives and consequences

- **Generic telemetry platform:** deferred. Multiple exporter schemas, live collectors, and general semantic conventions would expand validation beyond the supplied dataset without resolving the immediate evidence contract.
- **Copy the experiment unchanged:** rejected. Its fixed two-day inventory, developer paths, frontend cohort, and coupled quality flags are research conveniences, not a portable deployment contract.
- **Window-only extraction:** rejected as the completeness rule. It saves retrieval work but can lose parents, children, and completions. Explicit bounded results remain permitted, with partial coverage and no complete-trace claim.
- **Repeated full scans only:** retained as the correctness oracle and a declared fallback, not the preferred repeated-query path. Indexed preparation trades cold-start time and disk space for reuse; the measured research build does not establish compliance with judging resources.

The implementation must demonstrate cold-start and warm-reuse behavior within the runner's shared resource/time envelope, without requiring a shipped index or an LLM for extraction. Full inventories can be costly; exhausted budgets yield explicit partial or unavailable evidence and preserve completed work. New dates and component names must work without source edits, while incompatible schemas fail explicitly rather than being guessed into this adapter.
