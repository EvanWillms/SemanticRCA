## Execution protocol

For each slice:

1. Freeze the hypothesis, input hashes, required facts, expected contrasts, and pass/fail rule before implementing the feature. Expected facts must be authored from the fixture/source, not generated by the encoder under test.
2. Add only the smallest extraction/encoding change needed for that slice. Keep immutable outputs for each attempt; a fix gets a new run ID.
3. Decode retained facts without consulting raw records. Audit provenance separately against source records. Compare with independent expectations, including unknowns and conflicts.
4. Write a short result with `supported_on_fixture`, `falsified`, or `inconclusive`, the first differing fact, and the exact next action. Passing a tiny fixture is not general validation.
5. On failure, stop the dependent sequence and diagnose that boundary. Do not add another feature or model to hide the failure. Independent later hypotheses may be tested on authored correct inputs, explicitly labeled isolated rather than integrated.

The stop points are scientific decision boundaries, not additional permission gates. This request prepares the handoff; execution is a separate task. If later instructed to execute the sequence, advance on passing results without repeatedly asking for approval, within that instruction's scope.

## S01 — Structural equivalence and one contrast

**Hypothesis:** incidental identifier/order changes do not change the encoded structure, while one added operation does.

**Inputs:** only A1's seven-span T0, bijectively renamed/shuffled T1, and eight-span T2 with one added catalog child. Use declared synthetic timing units, but test structural facts here. Freeze the small operation dictionary and alias policy.

**Build:** minimal encoder and decoder for operations, parent references, recording-entity bindings, and exact occurrence counts. No automatic motif discovery. A compact normalized graph is a sufficient control.

**Measure:** exact recovered operation identities, edges, multiplicities, entity equality/distinctness; T0/T1 graph equivalence under the declared alias policy; T0/T2 one-node/one-edge delta. Do not compare provenance bytes for semantic equality.

**Pass:** every expected structural fact recovers; equivalent fixtures match; added occurrence remains visible. A constant labeler fails. Report bytes descriptively, with no compression gate.

**Stop:** publish the three packets, decoded facts and differences. A failure blocks integrated S02–S03. Zero model calls.

## S02 — A real recorded trace survives the representation

**Hypothesis:** the structural contract survives real mixed-type, repeated-operation telemetry without inventing status meanings.

**Inputs:** only R0, trace `9451fd8fdf746a80687451dae4c4e984`, retrieved by exact ID from the existing read-only trace index. Expected index inventory from the prior review: 37 records, 13 recording entities, one blank-parent root, 36 resolved links; statuses 33 `0`, two `200`, two `Ok`.

**Build:** an adapter from the nine raw fields into S01. Preserve raw operation, type, status, timing strings and source pointers. No new aliases inferred from names. Verify counts against extracted rows, then independently review the full retained fact sheet before encoder execution.

**Measure/pass:** all contracted raw values and structural facts round-trip exactly; evidence pointers resolve. No error/success/retry/target label is asserted without its own support. Retrieve complete indexed trace membership, not a file prefix; report instrumentation completeness as unknown.

**Stop:** one real packet and its audited differences. The recorded counts are a sanity check, not a substitute for full fact comparison. Zero model calls.

## S03 — Identity is not just an operation count

**Hypothesis:** two packets with the same operation counts remain distinguishable when one occurrence moves to a different recording entity.

**Inputs:** one repeated-operation synthetic fixture from S01 and a copy changing exactly one binding to a new entity. Independently list the expected same-entity/different-entity pair relations.

**Build:** only binding/equivalence handling missing from S01. Do not introduce topology parsing.

**Pass:** operation counts and edges stay equal; every planted identity-relation change is recovered; raw identities remain resolvable through provenance. Failure falsifies the binding contract. Zero model calls.

## S04 — Missing and conflicting evidence remain visible

**Hypothesis:** the packet distinguishes unresolved collection, conflicting identity, and an observed root-only trace.

**Inputs:** run two separate contrasts: (a) complete synthetic trace versus removal of one referenced parent with explicit incomplete retrieval; (b) unique span identity versus an added conflicting duplicate. Separately use R3, `33ac121d12f9d81f70a93424c7312544`, as the one-record root-only example.

**Build:** typed quality facts and lossless conflict retention. Do not repair a parent, choose a duplicate winner, or call a root-only trace fully instrumented.

**Pass:** exact missing-reference/conflict facts, both conflicting rows and their provenance retained, and `empty_recorded_children` distinguished from `unknown_structure`. Score each contrast independently so one success cannot mask another failure. Zero model calls.

## S05 — Edge-start offsets retain a timing signal

**Hypothesis:** a changed child timestamp changes the signed parent–child start offset even when durations, statuses and topology stay fixed.

**Inputs:** authored parent start `1000 ms`, child start `1003 ms`, and variant child start `1013 ms`. Expected offsets: `+3 ms` and `+13 ms`; delta `+10 ms`. Repeat with same-emitter and different-emitter bindings, retaining the latter's clock qualification.

**Build:** integer timestamp subtraction only. Do not require duration units to compute start offsets. Add a separate unknown-duration-unit check: preserve raw duration but leave derived endpoints unavailable. Synthetic known-unit timing may have endpoints; do not transfer that certainty to the real export.

**Pass:** exact offsets/delta, unchanged nonintervened facts, explicit clock/unit qualifications, and no automatic network-fault label. The official guide motivates edge timing but does not establish pure network transit time.

**Stop:** report start-offset fidelity separately from duration interpretation. Zero model calls.

## S06 — Status interpretation depends on a mapping

**Hypothesis:** identical raw status values can correctly yield unknown or reported error depending on documented producer semantics.

**Inputs:** one tiny authored span with raw status `14`; an otherwise identical input with an explicit synthetic producer contract mapping `14` to reported error; a third with that contract plus independently authored verification of successful enclosing-request outcome. Add one contract-defined non-error value as a negative control.

**Build:** exact context-scoped mapping lookup; separate span-status interpretation and request-outcome fields. Mapping evidence is an input, expected labels are not. The synthetic dictionary must never be applied to real benchmark spans.

**Pass:** unmapped `14` stays unknown; mapped `14` becomes reported error; the negative stays reported non-error; child error coexists with verified enclosing success. All raw values, scope, mapping version and evidence survive.

**Stop:** report this as a mapping-contract test. It cannot establish real-data error precision/recall because no real positive error ground truth has been established. Zero model calls.

## S07 — Dataset context can be parsed without guessing targets

**Hypothesis:** official naming/time conventions support deterministic context facts, including unseen identities, without supplying an individual span's missing backend.

Run two independent code-only checks; do not aggregate them into a single accuracy score:

- **Time:** authored metric/log epoch seconds and equivalent trace epoch milliseconds identify the same instant; UTC+8 calendar conversion round-trips. A factor-of-1000 mistake or adding eight hours to the epoch fails.
- **Names:** preserve and parse the documented `node-5.adservice-2` placement and mesh example `adservice-0.destination.frontend.adservice` into separately typed recording entity, direction and source/destination context. Freeze the grammar and expected fields. Test consistent unseen-name substitutions and a malformed name that must remain unresolved. Never strip meaningful service digits or assign these relationships to a particular DB span without join evidence.

**Stop:** two small result tables. No metrics/log retrieval or model calls. These checks can run independently of the encoder; connected claims require adding their facts to an actual packet afterward.

## S08 — Symbols reduce size at equal retained fidelity

**Hypothesis:** a dictionary/pattern representation is smaller than compact normalized JSON for a declared repeated-structure workload.

**Inputs:** independently correct versions of one repeated template instantiated 1, 10, and 100 times, with distinct occurrence identities and retained measurements. Compare normalized and symbolic representations with the same fact contract and provenance access policy. Include actual selected real packets only as a separately reported follow-up.

**Measure:** exact fact recovery, UTF-8 bytes, cold dictionary/schema overhead and explicitly amortized overhead. Actual model-token counts are a separate metric if the intended tokenizer is available; do not estimate them from characters. No model calls needed.

**Decision:** report the ratio at every size and any crossover. Support the narrow size claim only where the symbolic payload is smaller and all facts survive. No reduction is a valid negative result; do not relax fidelity or omit dictionary costs to obtain a win. A byte win alone does not support a model-cost claim.

## S09 — An LLM preserves the error boundary

**Hypothesis:** an LLM can describe code-extracted status facts without converting unmapped codes into errors or child errors into request failure.

**Inputs:** the three main S06 cases, independently correct in two representations: compact normalized JSON and symbolic packets, with equivalent definitions, context and evidence. No raw-row arm yet; no retrieval, diagnoses, or case narrative.

**Run:** one frozen available model/version, fixed prompt/schema/settings/output budget, three repetitions per case/format, isolated contexts and counterbalanced format order: **3 × 2 × 3 = 18 calls**. Record actual tokens, output, latency and cost where available. If model access is absent, mark not run; do not substitute fabricated responses.

**Question:** return raw status, mapping support, supported span interpretation, separately supported request outcome, exact evidence IDs and explicit unknowns. Arithmetic, entity extraction, and open-ended causal reasoning are outside this slice.

**Pass for labeling feasibility:** all required distinctions and evidence references are correct across runs, with zero unsupported error/success promotions. Check semantic entailment independently, not just JSON validity. Report each format separately.

**Representation benefit:** require no fact regression and lower total input tokens than normalized JSON on these matched inputs. An equally accurate but larger packet supports feasibility only. Any broader benefit needs another study; this sample does not estimate deployment accuracy.

**Stop:** publish all 18 outputs and claim-level adjudication. Only after this result choose the next single question—operation-description fidelity, edge-timing description, or a raw-row extraction comparison. Do not automatically launch the 126-call matrix.
