# Phase-isolated experimentation for MantisGrid

Status: proposed protocol, 2026-09-17. No experiments have been run under this protocol.

This structures validation of [contextual baselining](contextual-baselining.md) and its surrounding pipeline. It complements the [current specification](../../specs/001-candidate-recall-experiment/spec.md) and [assertions A1–A8](../../specs/001-candidate-recall-experiment/plan.md); it does not expand the next implementation experiment beyond A1's three structural fixtures.

## Principle: isolate the claim, then test the connection

The research chain is:

```text
describe observations → select references → qualify references
  → identify differences → assemble behavioral episodes → investigate causes
```

Each phase receives frozen, independently authored or reviewed inputs. Its expected outputs must not be generated by the implementation being evaluated. A downstream phase can be studied with correct authored inputs before an upstream implementation works. That establishes only the downstream capability under those inputs, not pipeline readiness.

Use two distinct run modes:

- **Isolated:** evaluate one phase against independently specified facts or acceptable outcomes. Freeze everything else.
- **Connected:** replace an authored input with an upstream phase's actual output on matched cases. Measure which errors appear, disappear, or propagate. Keep this result separate from isolated performance.

Some cases have no identifiable answer. The expected output may be a qualification, a set of compatible explanations, or an explicit unknown. Benchmark reason labels are not independent truth for intermediate descriptive or reference-quality claims.

## Experiment register

Every experiment starts as **not tested**. Each row is a separate study, not one end-to-end acceptance test.

| ID / phase | Isolated input and claim | Intervention and controls | Measurements and falsifier |
| --- | --- | --- | --- |
| E0 — Description | Authored observations and independent fact sheets. Descriptions preserve contracted structure, measurements, identities, and uncertainty. | Rename incidental IDs and reorder records; separately add an operation, change a replica, or remove collection coverage. | Exact fact recovery, invented/omitted facts, provenance resolution. Equivalent inputs must remain equivalent; planted differences and unknowns must survive. Start only with A1's three fixtures; quality extensions are separate A2 checks. |
| E1 — Reference selection | Correct observation packets with known context, candidate references, and a declared comparison question. Selection preserves comparability without conditioning away the investigated behavior. | Change workload/configuration while holding behavior fixed; change behavior while holding legitimate context fixed. Contrast latency conditioned on observed shape with structural comparison over a broader cohort. | Required context compatibility, reference membership under the declared policy, unsupported matches, informative unmatched observations retained. Fail if extra calls disappear because exact call counts were required to match. |

Qualification distinguishes eligible, qualified, and unavailable references. | Vary sample support, time coverage, missingness, regime mixture, context mismatch, and shared peer disturbance separately. Include contaminated history and unknown health. | Eligibility decisions, specific qualifications, unsupported eligibility, unnecessary refusals. Fail if typical is called healthy, peer agreement certifies health, or inadequate evidence supports an unjustified estimate. |
| E3 — Difference description | Authored observations plus frozen, qualified references. Comparisons recover planted descriptive differences without inferring causes. | Independently vary structure, resources, event frequency, outcomes, missing activity, and context. ## Required comparison families

E1–E3 must cover these families independently. No common scalar anomaly score is assumed.

| Family | Retain in the observation | Comparison trap to test |
| --- | --- | --- |
| Duration | Timing, units, operation, observed execution structure | Matching on duration hides the change; shape matching alone hides structural differences. |
| Structure | Operations, edges, multiplicity, supported ordering | Requiring the changed structure as a cohort key removes the contrast. |
| Resources | Level, trend, capacity, sampling, entity bindings | Different capacity or workload can make raw peer levels incomparable. |
| Frequency | Count, exposure, elapsed time, request volume | Normalization can hide falling total activity; raw counts can reflect changing exposure. |
| Outcomes | Raw status, known semantics, denominator, unresolved outcomes | Completion or an uninterpreted status does not establish business success. |
| Missing activity | Expected activity, demand, collection coverage | Missing telemetry does not establish missing execution. |

## Baseline-specific experimental matrix

Freeze a comparison question and one family first. Change one factor per fixture pair, then use a separately declared interaction set.

1. **Compatible unchanged behavior:** no planted difference; verify no invented departure. Natural random variation is described, not required to equal zero.
2. **Compatible changed behavior:** known change remains visible, with correct magnitude and direction.
3. **Context changed, behavior appropriate:** workload/capacity differences produce the declared contextual comparison or qualification.
4. **Investigated behavior changes cohort membership:** extra calls or reduced completed throughput must not silently remove the relevant observation.
5. **Insufficient support:** sparse samples, short coverage, constant/quantized values, and gaps exercise estimator-specific refusal or qualification rules.
6. **Conflicting reference views:** history and peers disagree; both findings and qualifications survive. No policy selects the largest departure after seeing results.
7. **Shared disturbance:** peers shift together while history differs; peer agreement cannot erase the historical departure.
8. **Potentially contaminated history:** the reference remains qualified unless independent information supports a stronger claim; robust estimation alone does not certify health.
9. **Collection loss versus activity loss:** separate fixtures produce different findings or an unresolved distinction when evidence is insufficient.
10. **Frozen versus updated reference:** new data can change a new baseline-relative result; old observations, reference versions, and findings remain reproducible. Include an ongoing disturbance that an adaptive reference could absorb.

The test author may know the planted mechanism to write expected facts. That knowledge is kept out of selectors, comparators, and diagnostic inputs. Real-data controls require independent justification; an interval without an injected-fault label is not automatically healthy.

## Run contract and acceptance

Before inspecting evaluated outputs, record:

```text
experiment_id / claim / explicit non-claims
input fixture IDs and hashes / independent expected facts or admissible outputs
observation and comparison question / context allowed to match or differ
reference membership, time bounds, version, eligibility policy
extraction, vocabulary, fidelity, comparison, and ranking policy versions
intervention / controls / fixed parameters
metrics with denominators / tolerances / acceptance rule
split membership / seeds / software and model configuration where applicable
output artifacts / errors / unknowns / conclusion / permitted next connection
```

For unambiguous deterministic contract fixtures, require zero invented or omitted required facts and all specified refusal/qualification cases to behave as declared. Numeric tolerances follow declared units and precision. These gates do not require zero statistical false positives in sampled real telemetry.

For empirical studies, preregister numerical targets, review/token budgets, repeat counts, and uncertainty reporting before running the held-out evaluation. This document deliberately supplies no unmeasured universal threshold. Use incident/window groups, not paraphrased requests, as the unit for splitting and uncertainty estimates. If groups share telemetry or reference intervals, purge the overlap or keep them together; document the dependency.

Keep separate statuses: **not tested**, **supported within tested scope**, **falsified**, and **inconclusive**. Low support or ambiguous evidence can make a study inconclusive; it cannot turn a failed deterministic fidelity check into a pass.

## Compression and reasoning experiment boundaries

E6 contains distinct runs, not a single combined score:

1. **Representation fidelity:** recover fixed factual answers from independently prepared representations. No LLM diagnosis required.
2. **Size at equal fidelity:** compare raw, normalized, and symbolic forms, including codebook and context metadata. Record cold and amortized overhead separately with an explicit reuse population.
3. **LLM factual use:** ask identical factual/comparison questions with the same model settings across formats. Repeat runs and counterbalance ordering.
4. **Evidence budget:** vary budget with a frozen selection policy; report accuracy versus actual total input tokens. If fitting the budget discards facts, call this a selection intervention rather than equal-fidelity compression.

E7 then asks whether reasoning improves diagnosis. A retrieval-enabled arm receives extra information and incurs extra cost; its advantage cannot be attributed solely to a better representation or model reasoning. Keep a fixed-evidence arm for that attribution.

An observationally ambiguous case should remain ambiguous even when a benchmark supplies one injected reason. Report benchmark answer accuracy separately from evidence-supported discrimination. World knowledge can generate hypotheses; a claim that the data discriminate them requires observable evidence.

## Connections and error attribution

After isolated checks, connect adjacent stages one boundary at a time using the same cases and frozen downstream policy:

```text
authored observations → actual encoder → E1
authored reference candidates → actual selector → E2
authored qualified references → actual qualifier outputs → E3
authored findings → actual comparator outputs → E4
authored episodes → actual assembler outputs → E5 / E7
```

Compare each connected result with its authored-input control. Attribute the first observable contract violation to its boundary; also report downstream amplification or recovery. Never use improved diagnosis accuracy to excuse lost required facts. Failed upstream phases do not prevent further isolated research, but block claims that the corresponding connected path is validated.

For later Track 1 evaluation, keep `scoring_points` evaluator-only. Group repeated windows and overlapping incident evidence before splitting; freeze development choices before held-out evaluation. Match predicted and expected incidents under a declared order-independent rule, then score time (the dataset's ±1-minute tolerance), exact component, reason, and joint tuples. Report one- and two-incident cases separately. Do not count multiple task projections of one incident as independent diagnostic successes.
